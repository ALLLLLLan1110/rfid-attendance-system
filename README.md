# RFID 一卡通刷卡考勤系统

这是一个本机运行的 KL9007U UHF RFID 学生签到/签退系统。已实现真实读卡、陌生卡登记、自动签到签退、重复刷卡防护、当前在校统计、历史查询和 SQLite 持久化。

## 快速启动

1. 给读卡器通电并连接 USB。
2. 确认设备管理器出现 CP210x COM 端口。
3. 双击 `启动系统.bat`。
4. 系统会自动打开页面；页面显示“COMx 已连接”后刷卡。

每次开机后双击 `启动系统.bat` 即可。它会打开一个本地服务窗口并自动打开网页；请让服务窗口保持打开，关闭浏览器不会停止系统。再次双击时，如果系统已经运行，只会重新打开网页。关闭本地服务窗口会停止系统；下次开机后再双击即可重新启动，不需要安装服务器或配置开机服务。

也可在根目录运行：

```powershell
npm start
```

运行自动测试：

```powershell
npm test
```

## 内部数据管理工具

需要修改学生资料、换卡、停用学生卡或修正考勤时间时，双击根目录的 `启动数据管理.bat`。工具在 Chrome 独立窗口打开，不依赖读卡器，也不需要先启动考勤主程序。每次保存前自动备份，可查看修改前后内容；旧版网吧数据仅供浏览。详细操作与恢复说明见 [内部工具说明](staff-tool/README.md)。

## 考勤演示流程

1. 刷陌生卡：系统友好提示，且不写入考勤。
2. 点击“登记陌生卡”，填写学号、姓名和班级；绑定后自动签到。
3. 10 秒内连续刷卡：系统显示重复刷卡已忽略，不修改数据库。
4. 超过 10 秒再次刷卡：系统自动签退，在原记录补充签退时间与时长。
5. 在考勤历史中按姓名、学号、班级、卡号或日期查询。

## 硬件与通信

- 读写器：KL9007U / UHFReader18 系列
- 标签协议：EPC Class 1 Gen 2（ISO 18000-6C）
- 通信：CP210x USB 虚拟串口，57600 bps
- 厂商 DLL：`vendor/UHFReader18CSharp.dll`、`vendor/Basic.dll`
- 桥接程序：`reader-bridge/bin/KL9007ReaderBridge.exe`，固定 x86
- 默认射频功率：8 dBm

Node.js 为 64 位，厂商 DLL 为 32 位，因此通过独立 x86 桥接程序读取 EPC，再把逐行 JSON 事件发送给 Node 服务。桥接程序对同一张持续停留的卡只发一个事件；卡离开约 3 秒后才能重新触发。设备蜂鸣器也只在新卡首次进入感应区时响一次。

可选环境变量：

```powershell
$env:READER_PORT = 'COM3'
$env:KL9007_POWER_DBM = '8'
npm start
```

## 数据与业务规则

- `students` 保存学号、姓名、班级和唯一卡号。
- `attendance_records` 保存一对签到/签退时间及在校分钟数。
- 最近没有未签退记录：本次刷卡为签到。
- 最近存在未签退记录：本次刷卡为签退。
- 距离上次有效操作不足 10 秒：判定为重复刷卡，不写数据库。
- 卡号仅接受 8—64 位偶数长度十六进制，并统一转为大写。
- 服务只监听 `127.0.0.1:8787`。
- 服务由 `启动系统.bat` 在可见命令窗口中启动，运行状态和报错会显示在该窗口。

数据库位于 `data/cybercard.db`。旧版网吧会员表仍保留在该文件中以避免破坏历史数据，但当前考勤代码不会使用它们。

## 仓库与数据安全

Git 仓库只保存源码、课程文档、启动脚本以及运行读卡器所需的桥接程序和厂家 DLL。`data/` 中的真实学生/会员数据、数据库备份、运行日志、测试截图和演示文稿构建缓存均由 `.gitignore` 排除，不会上传。克隆仓库后首次启动主程序会自动创建空数据库。

提交前可执行：

```powershell
npm test
git status --short
```

## 注意事项

- 不要同时运行厂商 Demo 和本系统，两者会争用 COM 口。
- `Basic.dll` 是厂家闭源 32 位 DLL，不要删除或改成 x64。
- 备份数据库时应停止服务并复制整个 `data` 目录，不能忽略 WAL 文件。
- 修改 `server.js` 或 `lib` 下代码后需要关闭服务窗口并重新双击启动；只修改 `public` 下页面文件时刷新浏览器即可。
- 考勤主界面正式部署前仍需增加管理员登录和权限控制；内部数据工具已提供修改审计及保存前备份。
